# Lunara: notes for coding agents

## publik API
- Base URL: https://publikhq.com/api/v1 (OpenAI Chat Completions, Responses, Anthropic Messages)
- Models: publik-fast, publik-balanced, publik-smart only; never a vendor model name
- Key: per-install `pk_` from POST /installs, stored in the iOS Keychain / Android Keystore vault (`publik-api-key`), never in the cycle database or a backup; the test-build-only launch value PUBLIK_API_BASE_URL points the app at a fake publik on 127.0.0.1, localhost or 10.0.2.2
- App token: VITE_PUBLIK_APP_TOKEN at build time (CI and release.yml: the PUBLIK_APP_TOKEN repo secret; the workflows fail when it is empty). `PUBLIK_DEV_APP_TOKEN` in `app/src/lib/publikBuild.ts` is a real token, the fallback for development and test builds only
- No amount of money for AI use anywhere in the app (founder rule, Nov 14 2026): AI use shows only as a percent with a bar (`publikStatusLine` / `PlanUseMeter`), or "Plan active" / "Plan limit reached". Never show a server text that names money (`withoutMoney`). `app/src/lib/noMoneyShown.test.ts` fails when an app file has "$" followed by a digit.
- Every funded account shows its use (`planUseFrom` in `lib/publikApi.ts`): a plan = "N% of your plan used · resets <day>"; prepaid use (`plan.kind` "pack") = "N% left" with a bar and NO reset day; the free starter = "N% of your free use left". Prepaid percent: GET /wallet `prepaid_remaining_percent` when publik sends it; until then `prepaidLeft()` counts it on the phone from the prepaid amount (balance minus starter) against the highest amount since the last top-up (`SK.publikPrepaidLevel`, never backed up). Never show the amount itself.
- 402 / plan limit: the app's own words (`planLimitText`: limit reached, when it resets, the storefront rule, "use your own key") plus error.top_up_url only on the US App Store storefront (below)
- When publik sends no claim_url, open nothing: show "publik sent no sign-in link. Try again."
- App Store rule 1.2: every AI answer has "Report this answer". The person picks a reason in the app; the in-app sheet opens `publikSupportUrl({ reason })` (`/in-app/support?app=lunara&app_name=…&topic=ai-answer&reason=<id>&reason_label=…`). Never put chat text or health data in that URL. The chat note says AI answers can be wrong and are not medical advice (`AI_ANSWER_NOTE`).
- The support URL also has `app_name` (the app name) and, for a report, `reason_label` (the words of the reason), so the page can show them. publik's page ignores parameters that it does not know; keep them.
- Settings → publik → Help and support opens `publikSupportUrl()` (`/in-app/support?app=lunara&app_name=publik+Lunara`).
- App Store rule 5.1.2(i): the publik agreement text names publik (publikhq.com) and the AI provider that answers. GET /api/v1/wallet sends `ai_providers` (company names); `aiProvidersFrom()` checks it and `publikProviderWords()` shows "publik sends it to the AI provider that answers: <list>". Without the field, the sentence has no company names. Never write a fixed list of companies. The phone keeps the last list (`SK.publikAiProviders`, `cachedAiProviders()`); offline it shows that list. If no list was ever read, the publik agreement cannot be accepted offline: "Turn on AI chat" stays off and `CONSENT_NEEDS_INTERNET` shows with "Try again".
- AI answers show a safe Markdown subset (`lib/chatMarkdown.ts` + `components/ChatMarkdown.tsx`: bold, italic, lists, headings as bold lines). React elements only: never `dangerouslySetInnerHTML`, never an anchor from answer text.
- Chats are not saved: say so (`CHAT_NOT_SAVED` under the message box). If you add saved chats, encrypt them on the phone and add "Clear chat".
- The store build has no local-network permission (no NSLocalNetworkUsageDescription): no screen lets a person enter a local AI address.
- Never print or log a key
- Docs: https://publikhq.com/llms.txt, https://publikhq.com/developers, https://publikhq.com/skills/api.md

## Sign in with publik
- The gate is `PublikGate` (`app/src/components/PublikGate.tsx`), which calls `ensureSignedIn()` from the module `app/src/lib/publik.ts` before onboarding, the PIN lock and the tabs. Keep the gate words in the module exactly as they are.
- "Use my own key" (bring your own key) must keep working: the Anthropic and OpenAI provider paths stay.
- "Use my own AI key" on the plan screen changes no AI setting (`applyChoiceToAi` acts only on publik). The gate opens Lunara AI on the key entry (`openAiKeyEntry` in `state/appStore.ts`). The provider, the model and the choice are saved only with a key: "Save connection" without a key saves nothing.
- The Settings AI row and Lunara AI use one rule for the AI choice in use: `activeAiProvider()` in `lib/publik.ts`.
- Telemetry sends only `app_opened` and `active_session`. Never add health data or cycle data to it.
- Test builds: `.github/workflows/mobile-test-builds.yml`. Do not build locally on the maintainer's Mac.
- Build settings live in `app/src/lib/buildFlags.ts`: `PUBLIK_GATE_MODE` (`required` default, `optional` for test builds only: a release build and an Xcode Release archive refuse it, so the App Store app always has the gate), `APP_STORE_BUILD` (no Claude subscription-token option; default on in the iOS app, `0` turns it off) and `PUBLIK_TEST_HOOKS` (`1`: a test build with the publik test hooks). Add no other switch. `app/src/lib/buildCheck.ts` lists what `vite build` refuses.
- The test hooks (PUBLIK_API_BASE_URL, PUBLIK_SELF_TEST, PUBLIK_TEST_SIGN_IN) need PUBLIK_TEST_HOOKS in the web bundle AND the native build (Android `-PpublikTestHooks=true`, iOS `PUBLIK_TEST_HOOKS=YES`). Never read them from an Android link (VIEW / BROWSABLE intent), never in a release build.
- iOS sign-in sheet: the app opens publik pages in its own SFSafariViewController (`publikSheetOpen` in `LunaraNativePlugin.swift`), not with @capacitor/browser. The sheet covers the web view, so JavaScript timers stop; the native side checks GET /wallet every 3 s on a fixed grid for 10 minutes (each check 8 s at most), closes the sheet when the claim (or the plan) is there, and sends `publikSheet` to JS. JS also checks at once when the sheet is closed by hand and when the app becomes active. The CI test `.github/scripts/ios-sheet-test.sh` (fake publik: `.github/scripts/fake-publik.mjs`) fails when the sheet does not close by itself within 5 s of the claim. Android: a Custom Tab cannot be closed by the app; the app checks when it comes back.
- The gate never shows raw error text (`problemText()`): a storage problem ("Transaction aborted", a closed database) is retried silently 3 times, then shows `STORAGE_PROBLEM`; a locked phone shows `PHONE_LOCKED`. Do not hold a storage transaction open across a network call.
- The iOS simulator has no storefront: `appStoreStorefront` answers none there, so no purchase button shows (`storefront.test.ts`).
- Every sign-out path calls `disconnectPublik()` or `deletePublikDataOnThisPhone()`: the phone forgets first, then revokes; telemetry stops; required mode returns to the gate. Do not add another sign-out path.
- AI is for adults only: `isAdultBirthYear()` (current year minus birth year 19 or more). Chat history never goes to a provider that did not receive it (`lib/chatHistory.ts`).
- The version and build number come from `app/package.json`; iOS copies them in `app/ios/App/Lunara.xcconfig` (`src/lib/nativeVersion.test.ts` checks). Each target has a `PrivacyInfo.xcprivacy`: update it when native code uses a new required-reason API or sends new data.
- Purchase links follow the App Store storefront (`lib/storefront.ts`): US storefront (`USA`) = "Get a plan", top-up links and prices as built; every other storefront, or an unknown one (also Android and the browser) = no purchase link, no purchase button, no price, and the text 'To get a plan, search for "publik" on Google.' "Connect your plan" and "Use my own key" stay everywhere.
- The app name is "publik Lunara" (`lib/appName.ts`); the label under the icon stays "Lunara". Keep the bundle ID, the package and the URL scheme `app.lunara.mobile`.
- Do not name or point to any other app in code comments or UI. Platform integrations (Apple Health, Health Connect) and AI providers are not apps in this sense.
- AI chat is optional. Without it, health and cycle data stays on the phone. Before AI chat sends anything to a provider (also with no category ticked), `lib/healthConsent.ts` shows "AI chat is optional" and waits for "Turn on AI chat"; "Not now" closes AI chat and sends nothing. A new provider or a newly ticked category asks again. Never send a message or health data without that answer.
- AI chat data is anonymized entirely. Only `makeAiPayload()` in `lib/aiPayload.ts` makes what a provider receives (the sender takes only its branded `AiPayload` type), for publik API and for an own key. No name, email, birth date, location, device or account ID, no tracker notes or other free text (only what the person typed into the chat), and days relative to today, never a calendar date. The publik install key stays in the Authorization header, for billing only. `lib/aiPayload.test.ts` fails when an identifier or a calendar date reaches the request.
- Dates in AI answers (`lib/answerDates.ts`): the model does not know today's date. The system prompt (`DATE_RULES`) has no date and no month name; it asks for `[[day:+18]]` and `[[range:+13..+23]]`. The phone replaces them with local dates only when it shows the answer (`renderAnswerDates`, counted from the day of the answer, `asOf`). `guardAnswerDates()` removes a calendar date that the model writes anyway ("[date left out]" plus one note). The chat history keeps the placeholders, so no real date leaves the phone.
- One forecast for every screen: `forecastOn()` in `lib/sharedForecast.ts` (buildCycleForecast plus the profile context, one cache). Today, the Calendar and the AI summary use it; each screen reads its inputs in a live query, so a changed log updates all of them. Do not call `predict()` for a new screen. `lib/sharedForecast.test.ts`: a period start logged today gives the same next period on Today and in the Calendar.
- The agreement screen lists exactly what is sent. The numbers live in `lib/aiLimits.ts`, and `lib/aiPayload.test.ts` compares the screen words with the limits. If you change what a message sends, change the screen words in the same commit.
- Every privacy claim uses `DATA_STAYS_ON_PHONE` ("Your data stays on this phone unless you turn on AI chat or encrypted backup."). Never write that data never leaves the phone.
